# 角色权限管理需求文档

> 文档版本：v1.0  
> 编写日期：2026-05-11  
> 适用系统：Smart Wrong Notebook（智能错题本）  
> 需求范围：模型服务商配置权限、老师角色、学生上传错题权限控制、老师分配错题给学生

---

## 1. 需求背景

当前系统已支持用户注册登录、错题上传、AI 分析、错题本管理、管理员后台用户管理等能力。随着使用场景从个人学习扩展到教学管理，需要引入更细粒度的角色权限控制：

1. 模型服务商配置属于系统级敏感配置，涉及 API Key、模型地址、模型选择等信息，仅应由管理员管理。
2. 需要新增“老师”角色，使老师可以上传错题，并将错题分配给指定学生进行学习和复习。
3. 学生仍沿用原系统普通注册用户的默认权限，但管理员需要能够控制每个学生是否具备“上传错题”能力。

本需求的目标是明确角色边界、功能入口、权限矩阵、业务流程、异常处理和后续实现建议，作为后续产品设计、开发、测试和验收依据。

## 2. 目标与范围

### 2.1 需求目标

- 建立管理员、老师、学生三类角色的权限模型。
- 限制模型服务商配置仅管理员可见、可访问、可修改。
- 新增老师角色，支持老师上传错题并分配给学生。
- 支持管理员按学生维度开启或关闭“上传错题”权限。
- 保证权限关闭、账号禁用、学生未激活等边界情况下的数据安全和流程可解释。

### 2.2 需求范围

本期包含：

- 角色定义与权限矩阵。
- 模型服务商配置入口和接口权限控制。
- 老师上传错题、选择学生、分配错题。
- 管理员在用户管理中维护学生上传权限。
- 学生端根据权限展示或隐藏上传入口。
- 权限变更后的已上传错题处理规则。
- 边界场景和异常处理。

本期不包含：

- 班级、课程、学校组织架构的完整建模。
- 家长角色、助教角色、教研员角色。
- 老师批改作业、评分、作业发布与提交闭环。
- 多租户学校级隔离。
- 支付、配额、计费等商业化权限。

## 3. 名词定义

| 名词 | 定义 |
|------|------|
| 管理员 | 系统最高管理角色，负责系统配置、用户管理、权限控制等后台能力。当前系统中对应 `admin` 角色。 |
| 老师 | 新增业务角色，可上传错题，并将错题分配给一个或多个学生。建议系统角色值为 `teacher`。 |
| 学生 | 默认学习用户，延续原系统普通注册用户能力。当前系统中对应 `user` 角色，建议产品语义展示为“学生”。 |
| 模型服务商配置 | AI Provider、API Key、Base URL、模型名称、连接测试、提示词等系统级 AI 配置。 |
| 上传错题权限 | 学生是否可以主动使用“上传错题/添加错题”功能的开关权限。 |
| 分配错题 | 老师将自己上传或创建的错题指定给学生，使学生可以在自己的错题列表或待学习列表中查看和练习。 |
| 激活用户 | `isActive = true` 的用户，可以正常登录和使用被授权功能。 |
| 未激活用户 | `isActive = false` 的用户，被管理员禁用，不能正常使用系统功能。 |

## 4. 角色定义

### 4.1 管理员

管理员负责系统级管理，包括：

- 管理模型服务商配置。
- 查看和管理用户列表。
- 设置用户角色：管理员、老师、学生。
- 启用或禁用用户账号。
- 控制每位学生是否允许上传错题。
- 兼容老师功能，可上传错题并分配给指定学生。
- 可查看必要的用户统计信息，如错题数量、练习记录数量等。

管理员不应被普通老师或学生管理。系统应保留至少一个可用管理员账号，避免所有管理员被禁用或删除。

### 4.2 老师

老师负责教学场景下的错题录入和分发，包括：

- 上传错题并触发 AI 分析。
- 编辑 AI 分析结果、知识点、答案、解析等错题信息。
- 将错题分配给指定学生。
- 查看自己创建或分配过的错题。
- 查看分配结果和学生接收状态。

老师不具备系统级配置权限，不应看到模型服务商配置入口，不应访问管理员用户管理能力。

### 4.3 学生

学生是默认学习用户，包括：

- 查看自己的错题。
- 复习、练习、筛选、打印自己的错题。
- 在管理员允许时，主动上传错题。
- 接收老师分配的错题。

当管理员关闭某个学生的上传权限后，该学生不能再主动上传新错题，但仍可查看、复习、练习已有错题以及老师分配给自己的错题。

## 7. 功能详细需求

### 7.1 模型服务商配置权限控制

#### 7.1.1 功能描述

模型服务商配置仅管理员可见、可访问、可修改。老师和学生登录后，不展示该配置入口；即使通过 URL 或接口直接访问，也必须被拒绝。

#### 7.1.2 前置条件

- 用户已登录。
- 系统已能识别当前用户角色。
- 模型服务商配置已有对应页面、弹窗或接口。

#### 7.1.3 操作流程

1. 管理员登录系统。
2. 管理员进入设置或后台管理区域。
3. 系统展示“模型服务商配置”入口。
4. 管理员查看或修改 AI Provider、API Key、Base URL、模型名称等配置。
5. 管理员保存配置。
6. 系统进行参数校验、保存配置，并返回保存结果。

#### 7.1.4 预期结果

- 管理员可正常查看和维护模型服务商配置。
- 老师和学生界面不显示模型服务商配置入口。
- 老师和学生直接请求相关页面或接口时，系统返回无权限错误。
- 敏感字段如 API Key 在前端展示时应脱敏，除非处于明确的编辑输入场景。

#### 7.1.5 异常处理

| 场景 | 处理规则 |
|------|----------|
| 未登录用户访问配置页面 | 跳转登录页或返回 401。 |
| 老师/学生访问配置页面 | 返回 403，并提示“无权限访问”。 |
| 老师/学生调用配置保存接口 | 返回 403，不修改任何配置。 |
| 管理员提交无效 Provider | 返回参数错误，保留原配置。 |
| 管理员提交无效 API Key 或模型不可用 | 保存前校验失败则提示失败原因；若仅保存不测试，则在连接测试时提示。 |
| 保存配置过程中服务异常 | 返回保存失败，不应产生部分写入或损坏配置文件。 |

### 7.2 新增老师角色

#### 7.2.1 功能描述

系统新增老师角色。老师可以上传错题，并将错题分配给指定学生。老师不具备管理员后台权限，也不具备模型服务商配置权限。

管理员兼容老师功能，可按同样流程上传错题并分配给学生。

#### 7.2.2 前置条件

- 管理员已创建或将某个用户设置为老师角色。
- 老师账号处于激活状态。
- 系统中存在至少一个激活学生，供老师分配错题。

#### 7.2.3 操作流程：设置老师角色

1. 管理员登录后台。
2. 管理员进入用户管理。
3. 管理员选择目标用户。
4. 管理员将用户角色设置为“老师”。
5. 系统保存角色变更。
6. 目标用户重新登录或刷新会话后，获得老师权限。

#### 7.2.4 预期结果：设置老师角色

- 用户角色变更成功后，用户列表展示为“老师”。
- 老师登录后可看到上传错题入口和分配错题能力。
- 老师无法看到模型服务商配置和管理员用户管理入口。

#### 7.2.5 操作流程：老师上传并分配错题

1. 老师登录系统。
2. 老师点击“上传错题”或“添加错题”。
3. 老师上传错题图片。
4. 系统进行图片预处理并调用 AI 分析。
5. 老师校对题目、答案、解析、知识点、学科等内容。
6. 老师选择一个或多个学生作为分配对象。
7. 老师确认保存并分配。
8. 系统创建老师侧错题记录，并为被分配学生创建可见记录或分配关系。
9. 学生登录后可在“老师分配”或自己的错题列表中查看该错题。

#### 7.2.6 预期结果：老师上传并分配错题

- 老师上传成功后，错题与老师建立创建关系。
- 被分配学生可以查看该错题。
- 未被分配学生不可查看该错题。
- 老师可以查看分配记录和分配对象。
- 老师不能分配给管理员或其他老师。

#### 7.2.7 异常处理

| 场景 | 处理规则 |
|------|----------|
| 老师账号被禁用 | 老师不能登录或不能继续操作。 |
| 老师上传图片格式不支持 | 提示支持的图片格式，不创建错题。 |
| AI 分析失败 | 保留图片和手动录入入口，允许老师手动填写后保存。 |
| 老师未选择学生 | 允许保存为老师自己的草稿/错题；若当前操作是“分配”，则提示必须选择学生。 |
| 老师选择了未激活学生 | 默认禁止分配，并提示“该学生已禁用，无法分配”。 |
| 老师选择了不存在的学生 | 返回参数错误，不创建分配关系。 |
| 老师选择了老师或管理员账号 | 返回参数错误，不创建分配关系。 |
| 分配过程中部分学生失败 | 建议采用事务处理；全部成功才提交。若产品允许部分成功，必须明确展示成功/失败名单。 |

### 7.3 学生上传权限控制

#### 7.3.1 功能描述

管理员可在后台按学生用户控制“上传错题”权限。该权限只影响学生主动上传新错题，不影响学生查看、复习、练习已有错题，也不影响接收老师分配的错题。

#### 7.3.2 前置条件

- 管理员已登录。
- 系统用户列表中存在学生角色用户。
- 系统已支持保存学生上传权限字段。

#### 7.3.3 操作流程

1. 管理员登录后台。
2. 管理员进入用户管理。
3. 用户列表展示学生用户及其“允许上传错题”开关。
4. 管理员打开或关闭某个学生的上传权限。
5. 系统保存权限变更。
6. 学生端根据最新权限展示或隐藏上传入口。

#### 7.3.4 预期结果

- 开关打开时，学生可以主动上传错题。
- 开关关闭时，学生端不展示上传入口。
- 学生直接调用上传、分析、保存错题接口时，后端返回 403。
- 已上传错题仍保留，不删除、不隐藏、不变更归属。
- 老师仍可给该学生分配错题。

#### 7.3.5 异常处理

| 场景 | 处理规则 |
|------|----------|
| 管理员关闭学生上传权限时学生正在上传 | 保存阶段必须重新校验权限；若权限已关闭，保存失败并提示“上传权限已被管理员关闭”。 |
| 学生上传权限关闭后访问上传页面 | 前端隐藏入口；若直接访问页面，展示无权限提示并引导返回错题列表。 |
| 学生上传权限关闭后调用 AI 分析接口 | 若该接口只服务上传流程，应返回 403；若其他功能复用该接口，则需按业务来源校验。 |
| 学生上传权限关闭后已上传错题 | 历史错题继续保留，学生可查看、编辑、复习、打印；不做自动删除。 |
| 管理员重新开启上传权限 | 学生刷新页面或重新登录后恢复上传入口，可继续上传新错题。 |
| 管理员误操作关闭权限 | 可立即重新开启；系统建议记录操作日志便于追溯。 |

### 7.4 学生接收老师分配错题

#### 7.4.1 功能描述

学生可以接收老师分配的错题。该能力不受学生主动上传权限影响，但受学生账号激活状态影响。

#### 7.4.2 前置条件

- 学生账号处于激活状态。
- 老师已成功分配错题给该学生。

#### 7.4.3 操作流程

1. 学生登录系统。
2. 学生进入错题列表、错题本或“老师分配”入口。
3. 系统展示老师分配给该学生的错题。
4. 学生查看题目、答案、解析和知识点。
5. 学生进行复习、练习、标记掌握状态或打印。

#### 7.4.4 预期结果

- 学生只能看到分配给自己的错题。
- 学生不能看到分配给其他学生的错题。
- 学生上传权限关闭时，仍可查看和复习老师分配错题。
- 学生账号禁用后，不能登录查看分配错题。

#### 7.4.5 异常处理

| 场景 | 处理规则 |
|------|----------|
| 学生账号被禁用后已有分配 | 分配关系保留，但学生不能登录查看；老师侧可看到该学生已禁用。 |
| 老师分配后删除原始错题 | 如采用共享分配关系，应同步不可见或提示已删除；如采用复制记录，学生副本可继续保留。需在实现前确定策略。 |
| 学生删除老师分配错题 | 建议仅删除学生侧可见关系或学生副本，不删除老师原始错题。 |
| 老师重复分配同一道错题给同一学生 | 系统应去重，提示“已分配”，不创建重复记录。 |

## 8. 数据与状态规则建议

### 8.1 角色字段

建议用户角色字段支持以下枚举：

| 角色值 | 展示名称 | 说明 |
|--------|----------|------|
| `admin` | 管理员 | 系统管理角色 |
| `teacher` | 老师 | 教学分配角色 |
| `user` 或 `student` | 学生 | 学习用户 |

考虑当前系统普通用户已使用 `user`，为降低迁移成本，建议：

- 数据库存储可继续使用 `user` 表示学生。
- 前端展示和需求文案统一称为“学生”。
- 如未来需要更清晰语义，可迁移为 `student`，但需兼容历史数据。

### 8.2 学生上传权限字段

建议在用户表增加布尔字段：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `canUploadErrors` | Boolean | `true` | 仅对学生角色生效，表示是否允许主动上传错题。 |

规则：

- 老师角色不受该字段限制，老师始终可上传错题。
- 管理员兼容老师功能，不受该字段限制，管理员始终可上传错题并分配给学生。
- 禁用账号 `isActive = false` 优先级高于 `canUploadErrors`。账号禁用时，所有登录后功能均不可用。

### 8.3 错题归属与分配关系

老师分配错题给学生有两种实现策略：

| 策略 | 描述 | 优点 | 风险 |
|------|------|------|------|
| 分配关系表 | 保留一条老师创建的错题，通过关系表记录分配给哪些学生。 | 数据不重复，老师修改可同步给学生。 | 学生个性化笔记、掌握状态需要额外建模。 |
| 复制学生副本 | 老师分配时为每个学生复制一条错题记录。 | 学生可独立编辑、标记掌握状态，贴合个人错题本。 | 数据冗余，老师后续修改不易同步。 |

建议采用“老师原题 + 学生副本”的混合策略：

- 老师保存原始错题。
- 分配时为学生创建个人错题副本，并记录来源老师和来源错题。
- 学生副本的掌握状态、笔记、复习计划独立维护。
- 老师原题后续修改不自动覆盖学生副本，避免影响学生已做笔记；如需要同步，另行设计“重新下发/更新分配”功能。

建议新增字段或关系：

| 对象 | 字段/关系 | 说明 |
|------|-----------|------|
| ErrorItem | `createdByUserId` | 创建者，可能是老师或学生。若沿用 `userId` 表示拥有者，则需另加来源字段。 |
| ErrorItem | `assignedByTeacherId` | 学生副本来源老师。 |
| ErrorItem | `sourceErrorItemId` | 学生副本对应的老师原始错题 ID。 |
| Assignment | `teacherId`、`studentId`、`sourceErrorItemId`、`studentErrorItemId`、`status` | 如需要分配状态统计，可单独建表。 |

## 9. 边界场景与处理规则

### 9.1 老师能否将错题分配给未激活学生？

默认不允许。

原因：

- 未激活学生无法登录，分配后无法完成学习动作。
- 向禁用账号分配会造成老师侧数据误解。

处理规则：

- 学生选择器默认过滤未激活学生。
- 如需要展示历史分配对象，应标记“已禁用”。
- 老师通过接口传入未激活学生 ID 时，后端返回 400 或 403，并提示该学生不可分配。

### 9.2 管理员关闭学生上传权限后，学生已上传的错题如何处理？

已上传错题保留。

处理规则：

- 不删除历史错题。
- 不隐藏历史错题。
- 不影响学生查看、编辑、复习、练习、打印历史错题。
- 仅禁止学生主动创建新的错题。
- 如学生在权限关闭前已进入上传流程，最终保存时以后端权限校验结果为准。

### 9.3 学生上传权限关闭后，老师还能否给该学生分配错题？

可以。

原因：

- 学生上传权限控制的是“学生主动上传”行为。
- 老师分配错题属于教学下发行为，不应受学生上传权限影响。

### 9.4 老师能否查看学生自己上传的错题？

本期默认不能。

原因：

- 当前需求仅要求老师上传并分配错题给学生。
- 查看学生个人错题涉及隐私、班级关系、授权范围等额外设计。

本需求不包含学生完成情况、学习跟踪、老师查看学生个人错题等能力。

### 9.5 老师能否编辑已分配给学生的错题？

建议规则：

- 老师可以编辑自己创建的原始错题。
- 若采用学生副本策略，老师编辑原题不自动覆盖学生副本。
- 若需同步更新，应提供明确的“同步到已分配学生”操作，并提示会影响哪些学生。

### 9.6 老师离职或账号被禁用后，已分配错题如何处理？

建议规则：

- 老师账号禁用后，不能登录、上传或继续分配。
- 已分配给学生的错题继续保留在学生侧。
- 老师原始错题继续保留，管理员可视情况转交或归档。
- 不建议因老师禁用而自动删除学生错题，避免影响学习记录。

### 9.7 管理员将学生改为老师后，上传权限开关如何处理？

建议规则：

- 用户变为老师后，老师上传能力由角色授予，不再受学生上传权限开关影响。
- 原 `canUploadErrors` 字段值保留，但前端不展示或标记为“不适用于老师”。
- 若后续从老师改回学生，则该字段继续生效。

### 9.8 管理员将老师改为学生后，老师创建的错题如何处理？

建议规则：

- 已创建的老师原始错题保留。
- 已分配给学生的副本或关系保留。
- 角色变更后，该用户失去新的分配权限。
- 是否允许继续查看过去作为老师创建的错题，建议保留只读或保留拥有者可见，避免数据丢失。

### 9.9 删除学生账号后的分配关系如何处理？

建议规则：

- 如系统允许删除学生，应级联删除学生个人错题副本和分配关系。
- 老师原始错题不受影响。
- 删除前应提示管理员该操作会删除该学生个人学习数据。

### 9.10 删除老师账号后的分配关系如何处理？

建议规则：

- 不建议直接删除有分配历史的老师账号。
- 如允许删除，学生副本继续保留，并将来源老师显示为“已删除用户”。
- 老师原始错题可由管理员选择删除、转交或保留归档。

## 10. 非功能需求

### 10.1 安全性

- 所有权限必须在后端接口校验。
- 前端隐藏入口仅作为体验优化，不作为安全边界。
- 模型配置中的密钥字段需脱敏展示，日志不得输出完整密钥。
- 老师分配学生时，后端必须校验目标用户真实存在、角色为学生、账号已激活。
- 学生访问错题时，必须校验错题归属或分配关系，避免越权访问。

### 10.2 可用性

- 用户管理列表应清晰展示角色、账号状态、学生上传权限。
- 学生上传权限开关应有明确说明：“关闭后学生不能主动上传新错题，但可继续查看已有错题和老师分配错题。”
- 老师分配学生时应支持按姓名、邮箱搜索。
- 未激活学生不应出现在默认可选列表中。

### 10.3 一致性

- 权限变更应尽快生效。建议接口每次请求实时读取权限，不仅依赖前端会话缓存。
- 如会话中缓存角色，角色变更后应要求用户刷新或重新登录，或实现会话实时刷新。
- 上传流程的分析、保存两个阶段都应考虑权限校验，避免只在入口处校验。

### 10.4 审计与日志

建议记录以下关键操作：

- 管理员修改模型服务商配置。
- 管理员修改用户角色。
- 管理员启用/禁用用户。
- 管理员开启/关闭学生上传权限。
- 老师分配错题给学生。
- 权限拒绝类接口访问。

日志应记录操作人、目标对象、操作类型、操作时间、结果，不记录敏感密钥明文。

## 11. 验收标准

### 11.1 模型服务商配置

- 管理员登录后可以看到模型服务商配置入口。
- 老师和学生登录后看不到模型服务商配置入口。
- 老师和学生直接调用配置读取/保存接口返回无权限。
- 管理员保存配置成功后，系统使用新配置。

### 11.2 老师角色

- 管理员可以将普通用户设置为老师。
- 老师登录后可以上传错题。
- 老师可以选择激活学生并完成错题分配。
- 老师不能分配给未激活学生、管理员或其他老师。
- 老师不能访问用户管理和模型服务商配置。
- 管理员可兼容执行老师的上传错题和分配错题能力。

### 11.3 学生上传权限

- 管理员可以对每个学生开启或关闭上传错题权限。
- 权限开启时，学生可以正常上传错题。
- 权限关闭时，学生看不到上传入口。
- 权限关闭时，学生直接调用上传保存相关接口返回无权限。
- 权限关闭后，学生历史错题仍可查看和复习。
- 权限关闭后，学生仍可接收老师分配错题。

### 11.4 数据安全

- 学生不能查看其他学生错题。
- 老师不能查看未分配给自己管理范围内学生的数据。本期若未建立师生关系，则老师仅能查看自己创建和分配的错题。
- 删除或禁用用户不会导致不相关用户数据丢失。

## 12. 测试建议

### 12.1 单元测试

- 角色判断函数：`admin`、`teacher`、`user` 权限判断。
- 学生上传权限判断：激活状态、角色、上传开关组合。
- 分配目标校验：目标不存在、非学生、未激活、重复分配。

### 12.2 接口测试

- `/api/settings` 读取和保存仅管理员可用。
- 学生上传权限关闭后，上传分析和保存接口拒绝学生请求。
- 老师和管理员上传错题接口请求成功。
- 老师和管理员分配错题接口拒绝无效学生 ID。
- 普通学生不能调用老师分配接口。

### 12.3 端到端测试

- 管理员关闭某学生上传权限，学生端上传入口消失。
- 学生权限关闭后刷新页面、重新登录均不能上传。
- 老师上传错题并分配给学生，学生端可查看。
- 管理员上传错题并分配给学生，学生端可查看。
- 老师尝试分配给未激活学生，系统提示失败。
- 老师和学生均无法看到模型服务商配置入口。

## 13. 补充建议

1. 建议优先统一权限模型，提供集中式权限判断方法，避免各页面和接口分散写角色判断逻辑。
2. 建议将“用户角色”和“功能权限”分层设计：角色提供默认权限，特定用户权限开关用于细粒度覆盖。
3. 本期分配对象限定为单个或多个学生，不设计班级、学生分组、批量导入学生等能力。
4. 建议保留学生上传权限的操作日志，便于处理“为什么某学生不能上传”的客服或运维问题。
5. 建议在用户管理中增加筛选项：角色、账号状态、上传权限，便于管理员维护大量用户。
6. 建议在老师端分配错题后提供结果反馈，例如“已分配给 3 名学生”，并可查看分配名单。
7. 本期不提供学生完成情况、学习跟踪、老师查看学生个人错题等能力。
